Router Benchmark 雙軌對照
32 案同題 · ChatGPT mock vs Rev2 Phase 3

兩套系統對「該不該答」不一致的有 13 案，其中 2 案是該交給別的工具

左軌是 ChatGPT 產出的 router mock：一張查表把 8 維小數 profile 對應到 20 種策略名稱，不執行任何流程。 右軌是本專案的 Rev2 Phase 3 實作：同樣 32 題真的跑過 CaseOrchestrator。 Rev2 的核心改動是把 LLM 降級成提名者——主張變成四元組、似然變成定性等級再查表、實驗登記由確定性程式做。 Phase 2 再往上加的都是確定性守門件：EVOI 決定實驗該不該做、三擾動分開回報、Chao1 說假設空間找完了沒有、 conformal 只對可交換的題型給覆蓋保證。檢查也從 9 項加到 14 項，全部改成「自己重算一次再比對」。 Phase 3 再加一層：把學習接上，然後連跑 50 案看它到底有沒有在學—— 單案測不出學習，一個 case 的 Beta 後驗與校準曲線都沒有意義。

32 案裡有 案的行為改變。三個方向：拒答不再只是一句話、專業數值模型該轉介出去、有機器驗證器時不必再花一次 LLM 批判。

結構比較

三套實作各自有什麼

這一節不是評分，是清點。左欄的「不存在」不等於做錯——mock 的目的是示意路由表；但它同時意味著有幾類錯誤在那個結構裡量不出來。

Phase 1 → Phase 2

這一版把「保證」從形狀填成數字

Phase 1 的 Assurance 三層只有能力層是真的：覆蓋層一律 null，穩定層只有機率擾動。 Phase 2 把另外兩層填上，而且每一個數字都要能被獨立重算——重算不出同一個值的數字，在這裡算是壞掉。

檢查有效性

把守門件換成壞的，檢查抓不抓得到

通過率本身證明不了任何事：一份檢查如果恆真，100% 通過與 0% 一樣沒有資訊。所以刻意注入壞的守門件，看有多少「受影響案例」變紅。 受影響 = 該 mutation 有機會改變行為的案例；抓到率用 抓到 / 受影響 計算。有些守門件需要配套的故障、或需要跨多次執行才觀察得到，下面照實標示並註明由哪個測試覆蓋。

Phase 3 · 序列型

連跑 50 案，看四條學習曲線走對方向沒有

每個 agent 有一個「真實能力」參數，系統不知道，要自己從結果裡學回來； 答對與否由 (agentId, caseId) 的穩定雜湊決定，所以整串完全可重放。 先知道正確答案、再看它收斂到哪裡——這是唯一能驗證「學習有沒有在學」的辦法。

Rev2 新增

模型供給不足時，系統會自己降級

同一題（R3 高壓保護回路），只改變「可用的模型家族數」。多 LLM 的價值完全來自錯誤獨立性；獨立性不可得時，多跑 agent 只是把成本乘以 N，還會製造虛假信心。
